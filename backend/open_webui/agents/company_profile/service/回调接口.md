# 企业画像回调接口联调改造要求

当前企业画像服务已经可以生成 `task_id` 和 `pdfurl`，需要在任务完成后，主动回调对方接口。

## 1. 回调地址

请求方式：

```text
POST
````

测试环境回调地址示例：

```text
http://172.19.59.163:8096/api/CompanyProfile/ProfileCallback
```

实际回调地址由调用方在 `POST /api/task` 请求的 `callback` 字段中提供。企业画像服务必须使用当前任务携带的地址，不使用固定环境变量覆盖。

## 2. 回调 body 明文

任务完成后，生成如下 JSON：

```json
{
  "task_id": "<任务ID>",
  "pdfurl": "<企业画像PDF地址>"
}
```

其中：

```text
task_id 使用当前任务生成的 task_id
pdfurl 使用当前任务生成的 PDF 访问地址
```

## 3. body 加密要求

body 不能直接发送 JSON 明文，需要先 AES 加密。

加密配置：

```text
算法：AES
模式：CBC
填充：PKCS7
密钥长度：128 bits
字符编码：UTF-8
输出格式：Base64
```

body 加密密钥：

```text
key: s+pongX3NfI_9.W!
iv:  #*2+8e!C@&uP4Uxf
```

最终请求 body 直接发送加密后的 Base64 字符串，不要再包一层 JSON。

正确形式：

```text
<encrypted_body_base64>
```

不要发送成：

```json
{
  "data": "<encrypted_body_base64>"
}
```

## 4. token header 明文

每次请求需要生成 token 明文：

```json
{
  "IP": "<企业画像服务所在服务器IP>",
  "date": "<当前时间>"
}
```

说明：

```text
IP 填企业画像服务所在服务器 IP
date 填当前时间
```

date 格式按对方示例：

```text
yyyy-MM-dd HH:mm
```

示例：

```json
{
  "IP": "172.19.xx.xx",
  "date": "2026-07-08 16:45"
}
```

## 5. token 加密要求

token 也需要 AES 加密。

加密配置同 body：

```text
算法：AES
模式：CBC
填充：PKCS7
密钥长度：128 bits
字符编码：UTF-8
输出格式：Base64
```

token 加密密钥：

```text
key: s(e^vry18$cG~1~.
iv:  qADVLa&=eJ,uw=pG
```

加密后的 token 放到请求头：

```text
token: <encrypted_token_base64>
```

注意 header 名是 `token`，不是 `Authorization`。

## 6. 请求格式

请求结构：

```text
POST /api/CompanyProfile/ProfileCallback

Headers:
token: <encrypted_token_base64>
Content-Type: application/json

Body:
<encrypted_body_base64>
```

body 使用 raw 字符串发送。

## 7. 响应处理

对方响应 body 使用请求 body 相同的 BODY KEY/IV 和 AES-CBC-PKCS7-Base64 规则加密。解密后的 JSON 示例：

```json
{
  "code": 0,
  "msg": "操作成功"
}
```

只有同时满足以下条件才算本次回调成功：

```text
1. HTTP 状态码为 2xx
2. response body 能使用 BODY KEY/IV 成功解密
3. 解密结果是合法 JSON
4. 解密结果中的 code 等于 0
```

任何条件不满足均视为本次发送失败，但不得因此改变已经完成的企业画像任务状态。

单个成功任务最多发送 3 次，首次发送包含在内。前三次均失败后停止发送，调用方仍可通过任务状态查询获得 PDF 地址。

## 8. 建议实现方式

在基础部署服务 API Gateway 中提供独立通用回调模块，例如：

```text
app/callback_client.py
```

核心函数：

```text
send_callback(callback_url: str, payload: dict, config: CallbackConfig) -> CallbackResult
```

内部流程：

```text
1. 组装 body 明文 JSON
2. 使用 body key/iv 加密 body
3. 组装 token 明文 JSON
4. 使用 token key/iv 加密 token
5. POST 请求当前任务携带的 callback 地址
6. 记录请求结果
7. 返回回调状态
```

## 9. 配置要求

以下内容不要硬编码在业务逻辑里，优先放到配置文件或环境变量：

```text
CALLBACK_MODE
CALLBACK_BODY_AES_KEY
CALLBACK_BODY_AES_IV
CALLBACK_TOKEN_AES_KEY
CALLBACK_TOKEN_AES_IV
CALLBACK_SERVER_IP
CALLBACK_TIMEOUT
CALLBACK_MAX_ATTEMPTS
CALLBACK_RETRY_DELAY_SECONDS
```

## 10. 日志要求

必须记录：

```text
task_id
pdfurl
callback_url
HTTP 状态码
原始响应 body
回调成功/失败
异常信息
```

不要在日志中打印 AES key、iv。

token 密文和 body 密文也尽量不要完整打印，最多打印前后少量字符用于排查。

## 11. 最小联调验证

先写一个最小测试脚本，不接入主流程，验证：

```text
1. 服务所在机器能访问 172.19.59.163:8096
2. AES-CBC-PKCS7-Base64 加密结果格式正确
3. token header 能被对方接口识别
4. body 密文能被对方接口识别
5. 接口返回结果能被完整记录
```

测试跑通后，再接入企业画像任务完成后的正式回调流程。
